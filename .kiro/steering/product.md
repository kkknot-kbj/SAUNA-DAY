# SAUNA DAY — プロダクト思想

## 一行で言うと

**サウナ施設を検索するアプリではなく、サウナを起点に休日の過ごし方を決めるアプリ。**

メインコピー：

> 次の休日、
> サウナから決めよう。

## 主役は常にサウナ

ユーザーは「サウナに行きたい」と思ってこのアプリを開く。
そこから、サ飯 / 観光 / アクティビティ / 温泉 / 宿泊 を含む「休日の過ごし方」まで決まる。

**IMPORTANT: 旅行・観光・グルメを前面に出しすぎてはいけない。** それらはサウナを中心に据えた休日の構成要素であり、主役ではない。一般的な旅行プランアプリになった時点で、このプロダクトは失敗している。

判断に迷ったら「サウナ選びの体験が良くなるか？」を基準にする。

## IMPORTANT: AIを前面に出さない

AIは裏側で休日プランを組み立てるためだけに使う。ユーザー体験の主役ではない。

以下は**すべて禁止**：

- 「AIがおすすめします」等のAI言及コピー
- AIチャット画面 / チャットUI
- 「✨あなたにぴったり✨」のような煽り表現
- キラキラした演出、魔法っぽいローディング
- 「生成中...」など生成AIを想起させる文言（「休日プランを組み立てています」等に置き換える）

サウナ検索は**AIに行わせない**。DBに対する検索・フィルタ・ランキングで実現する。

## ユーザーに感じてほしいこと

目指す反応：

- 「このアプリ、サウナ選びめちゃくちゃ分かりやすい」
- 「サウナを決めたら休日まで決まるの便利」

避けたい反応：

- 「AIアプリだ」
- 「よくある旅行アプリだ」

## 会員登録の扱い

**閲覧・検索に会員登録は不要。** 最初から登録を要求しない。

登録を求めるのは「行きたい」を保存するときだけ。
ゲスト状態では検索条件や直近閲覧を端末側に一時保存し、登録後にアカウントへ移行する。

## MVPのスコープ

含む：探す / 条件設定 / 検索結果 / サウナ詳細 / 休日プラン / 行きたい / 保存プラン / 認証

含まない：
- **予約機能そのもの**（各施設の公式予約ページへ遷移するのみ。予約URLはDBに保持）
- メールアドレス・パスワード認証（Apple / Google のみ）
- レビュー・口コミ投稿
- 地図上での検索

## 開発フェーズ

| Phase | 内容 |
|---|---|
| 1 | UI / ナビゲーション / モックデータ |
| 2 | Supabase DB / 検索 / フィルタ |
| 3 | サウナ詳細 / 行きたい |
| 4 | 認証 |
| 5 | サ飯 / 観光 / 宿泊の関連付け |
| 6 | 休日プラン生成 |
| 7 | AI統合 |

**最初からすべてを完成させようとしない。** フェーズ順に積み上げる。
