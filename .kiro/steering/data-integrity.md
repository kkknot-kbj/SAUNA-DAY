# データ正確性のルール

このプロダクトの信頼性は「書いてある情報が正しいこと」に依存する。
営業時間が違えば休日が台無しになる。ここは妥協しない。

## IMPORTANT: DB は Single Source of Truth

施設に関する**事実情報**は必ずDBを正とする。

事実情報の定義：

- 施設名、住所、座標
- 営業時間、定休日
- 料金、人数（最小/最大）
- サウナタイプ、熱源、温度
- クールダウンの種類・水温・水深・飛び込み可否
- 外気浴、景色、貸切情報
- 利用条件（水着/裸/子ども/ペット/撮影 等）
- アクセス、駐車場
- 予約URL、公式URL、電話番号

**これらをAI（LLM）に生成・補完・推測させてはいけない。**

## IMPORTANT: 不明な情報は「不明」と表示する

値が存在しない場合：

- DBには `NULL` を保持する。`0` や `""` や `"未定"` で埋めない
- UIには **「不明」** と表示する
- 「だいたい〇〇円くらい」「おそらく〇時まで」のような推測を出力しない
- 平均値や近隣施設からの類推で埋めない

```ts
// OK
{sauna.priceMin === null ? '不明' : `¥${sauna.priceMin.toLocaleString()}〜`}

// NG — 推測で埋めている
{sauna.priceMin ?? '¥3,000〜'}
```

## 検索はAIに行わせない

サウナの検索・フィルタ・ランキングは **Supabase PostgreSQL への問い合わせと決定的なスコア計算**で実装する。

- 必須条件を満たさない施設は**除外**する（スコアを下げるのではなく落とす）
- 希望条件は一致数を数える
- 距離 / 料金 / 人気 / ユーザーの過去の選択 を加味してランキング

**スコアの重みをコードにハードコードしない。** `search_weights` テーブル（またはPhase 1では設定モジュール）から読み、後から変更できるようにする。

初期値：

| 要素 | 重み |
|---|---|
| condition_match | 55% |
| distance | 20% |
| price | 10% |
| popularity | 10% |
| preference | 5% |

ランキング理由はユーザーに開示できるようにする（「なぜこの順番？」）。そのためスコア計算は各要素の内訳を返す構造にする。

## IMPORTANT: 「近くにある」と「入れる」を区別する

**単一のbooleanで環境を表現してはいけない。**

| 意味 | 保持場所 |
|---|---|
| 川が近くにある / 川が見える | `sauna_environments` (key=`river`, proximity=`nearby`/`view_only`/`on_site`) |
| 川に入れる（クールダウンとして） | `sauna_cooldowns` (key=`river`) |

海・湖も同様。「海が見える」と「海に入れる」は別情報。

これを混ぜると「川に飛び込みたい人」と「川を眺めて外気浴したい人」に同じ検索結果が出る。プロダクトの核心を損なうので必ず分ける。

## AI に渡してよいもの / 渡すもの

休日プラン生成でAIを使うとき：

**渡す**（DBから取得した正確なデータのみ）

- 選択されたサウナのレコード
- 紐付いた `restaurants` / `spots` / `hotels` の候補（距離・移動時間・料金・営業時間を含む）
- ユーザーの条件（日付、人数、出発地、移動可能時間、日帰り/宿泊）

**AIに任せてよい判断**

- 候補の中からどれを選ぶか
- 訪問順序
- 各項目の時刻の割り当て
- 「なぜこの流れが良いか」の短い説明文

**AIに絶対させないこと**

- 候補リストに存在しない施設名を出す
- 料金・営業時間・所要時間の数値を作る
- 施設の設備や特徴を記述する

## 構造でAIの捏造を防ぐ

プラン項目は自由テキストを持たせない。DBレコードへの参照で表現する。

```ts
type PlanItem = {
  startTime: string;              // AI が決めてよい
  refType: 'sauna' | 'restaurant' | 'spot' | 'hotel';
  refId: string;                  // 候補リストに含まれるIDのみ許可
  note: string | null;            // AI が書いてよい短い一言
};
```

施設名・料金・営業時間は**レンダリング時にDBから引く**。AIの出力をそのまま表示しない。

生成結果を保存する前に、`refId` がすべて候補リストに含まれることを**バリデーションする**。含まれないIDが返ってきたらその項目を破棄する。

## モックデータの扱い

Phase 1 のモックデータも上記ルールに従う。

- 最低20施設、地域を分散させる
- 自然環境 / クールダウン / サウナタイプ / 料金 / 距離 / 貸切 / 体験 をそれぞれ変える
- 検索条件を変えると結果が変わることを確認できる構成にする
- **一部の施設は意図的に `NULL` を含める**（「不明」表示の検証用）
- 実在施設を模すが、実在の施設名・電話番号・URLをそのまま使わない
